# 04 · 兼容与版本

## 1 · 这份包声明了什么

来自包内 `pack.mcmeta`（**逐字节就是你下载到的那个**）：

```json
{
  "pack": {
    "pack_format": 81,
    "supported_formats": {
      "min_inclusive": 48,
      "max_inclusive": 82
    },
    "description": "§cDVH v3.0 §7+ §9DBB\n§7Scale 22, max_health up to 95325"
  }
}
```

- `pack_format: 81` → 目标版本是 **1.21.7 / 1.21.8**；
- `supported_formats: 48–82` → 版本号落在这一段的游戏**不会拒载**（1.21.6 是 80，在区间内）；
- 描述串里的 `DVH v3.0` 与 `DBB`（Doom Bossbar）是**包内显示名**，它按"包内描述"惯例保留了原始写法；
  发行版号以本仓库的 Release 标签为准（当前 `v3.0.0`）。二者是同一个版本。

## 2 · 版本矩阵

| 你的环境 | 能不能装 | 说明 |
|---|---|---|
| Minecraft **1.21.7 / 1.21.8** | ✅ 目标版本 | `pack_format` 完全匹配 |
| Minecraft **1.21.6**（`pack_format` 80） | ✅ 可以 | 落在 `supported_formats` 区间里；**本版没有在 1.21.6 上跑过真机验证**，遇到问题请报 Issue |
| Minecraft **1.21.5 及更早**（`pack_format` < 48） | ❌ 不行 | 包会被判版本不符并拒绝加载 |
| Minecraft 快照 / 未来版本（`pack_format` > 82） | ⚠️ 未声明 | 会因版本号不在区间里被拒；把 `max_inclusive` 调大可以试，出问题自负 |
| 单人存档 / 服务器（原版 · Fabric · Paper） | ✅ 都行 | 服务器放 `world/datapacks/`；纯数据包，不需要模组侧支持 |
| 和其它数据包共存 | ✅ 一般没问题 | 本包不改原版房规、不动刷怪、不改原版血量上限；只用自己命名空间下的 storage / 计分板 |

**要不要开实验性玩法**：不用。包里只用了稳定的数据包能力（函数宏、实体自定义数据、Bossbar、附魔 JSON）。

## 3 · 升级 / 降级

### 升级（例如以后出 v3.0.1）

1. 记下当前正在用的版本（`dist/` 里的 zip 文件名）；
2. `/function doom.virtual.health:__unload__` 先摘干净（避免实体上残留旧标签/血条）；
3. 删掉旧目录、放入新的 `doom.virtual.health/`、`/reload`；
4. 想让世界里的老怪重新获得虚拟血量：对它们重新 `auto_init`（`/data modify entity … data.dvh …`）或 `api/create`。

### 降级

包内没有"数据迁移"这一步，降级步骤与升级相同（摘干净 → 换目录 → `/reload`）。
注意降级可能让**新版才有的字段**被忽略（例如新加的 `on_death` 语义变化），**先备份存档**。

### 改哪些文件要重启服务器

| 改动 | `/reload` 够不够 |
|---|---|
| `function/**/*.mcfunction` | ✅ `/reload` 就够 |
| `tags/function/*.json`（含 `#minecraft:load` / `#minecraft:tick`） | ✅ `/reload` 就够 |
| `enchantment/vitality.json` | ❌ **必须重启服务器**（附魔注册只在启动时读） |
| `pack.mcmeta` | 需要重新加载数据包（单人重进世界 / 服务器 `/reload` 后若没生效就重启） |

## 4 · 版本号规则（本仓库自 v3.0.0 起采用）

```
v<MAJOR>.<MINOR>.<PATCH>              正式版       例：v3.0.0
v<MAJOR>.<MINOR>.<PATCH>-beta.<N>     预发布       例：v3.1.0-beta.1
v<MAJOR>.<MINOR>.<PATCH>-rc.<N>       候选（可选） 例：v3.1.0-rc.1
```

| 位数 | 什么时候升 |
|---|---|
| **MAJOR** | 玩家/整合包作者**必须动手**才能继续用（storage 字段改名、函数路径改名、包结构变化、要开不同的实验性旗标），或者换 Minecraft 大版本后的首次适配 |
| **MINOR** | 向后兼容的**新能力 / 新内容**：新增可自定义字段、新增 API、新增预设 |
| **PATCH** | **修 bug、性能、文档、以及不改行为的重打包**（清幽灵文件、重算 sha256、修正包内描述、工程整理） |

**Minecraft 版本不进版本号**：它只写在 `pack.mcmeta` 与本文第 1~2 节，附件名里也不带。
这样换 MC 版本时不必把历史附件全部改名。

**Release 边界**：产物（包体或 zip）任何一个字节变了 ⇒ 必须升 PATCH 并重发附件；只有文档/元数据变化才可以直接提交不发版。
一个版本号只对应一份产物，永不复用；已发布的标签**不移动、不删除**。

## 5 · 已知的"改不动"的部分

这些是原版机制决定的，不是 bug（完整清单见仓库根 README 的 Edge Cases 节）：

- 单 tick 内超过 512 HP 的**一次性**伤害会被探针截断（E6）；
- 单 tick 内超过 512 HP 的**一次性**治疗会丢（E7）；
- 未加载区块里的实体不参与 tick 检测，血量不会变（E8）；
- `/kill` 直接杀死的实体**不会**触发 `on_death`（E10）；
- 玩家实体支持虚拟血量，但死亡掉经验/背包是原版行为，不由本包控制（E12）。
